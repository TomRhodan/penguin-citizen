Handbook

    Troubleshooting & FAQ

    Solutions to common problems, log file locations, and known limitations.

    Log File Locations

    When something goes wrong, these log files contain diagnostic information:

    • Penguin Citizen application log - ~/.config/penguin-citizen/logs/
    • Penguin Citizen debug log - ~/.config/penguin-citizen/logs/debug.log
    • Wine/Game output - Shown in the Launch page log panel during gameplay

    Set the log level to Debug in Settings for the most detailed output when diagnosing issues.

    Common Problems

    Game won't launch

    • Verify a Wine runner is selected and installed (check the Wine Runners page)
    • Run the system check on the Installation page to verify prerequisites
    • Check the Launch page log output for error messages
    • Try a different Wine runner - some versions work better than others

    System check failures

    • Inotify mapcount too low - Set vm.max_map_count=1048576 in /etc/sysctl.d/ and run sudo sysctl --system. See the LUG Wiki for distribution-specific instructions.
    • File descriptor limit too low - Add * soft nofile 524288 and * hard nofile 524288 to /etc/security/limits.conf and restart your session.
    • No Vulkan support - Install the appropriate Vulkan driver for your GPU (mesa-vulkan-drivers for AMD/Intel, nvidia-vulkan-icd for NVIDIA).

    Poor performance

    • Enable ESync and FSync on the Launch page
    • Enable DXVK Async to reduce shader compilation stuttering
    • Enable GameMode to automatically optimize CPU/GPU performance
    • Use the USER.cfg editor to lower graphics settings
    • Enable MangoHUD to monitor CPU/GPU usage and identify bottlenecks
    • Ensure DXVK is installed and up to date (check Wine Runners)
    • Use GPU-specific options: NVIDIA DLSS for frame generation or AMD RADV Zero VRAM / Nogttspill for AMD stability

    RSI Launcher won't start or is corrupted

    Use the Repair function on the Dashboard. It renames the current Wine prefix, performs a fresh installation, and automatically restores game data. See Dashboard - Installation Repair for details.

    If automatic repair doesn't help:

    • Check the log output for specific error messages
    • Enable In-Process GPU on the Launch page if the launcher shows a black or white window
    • Try a different Wine runner

    From Wine 11.14 on, the wine process the app starts exits by itself a few seconds later — the launcher then keeps running inside the wine session. The app used to report that as "exited", which sent the interface back to its idle state and made a second attempt collide with the launcher that was still running. It now waits until no process is left in the prefix. When the launch console says the RSI Launcher is still running and it is waiting for it, that is the normal course of events.

    Gamescope issues

    • Gamescope not installed - Install gamescope via your package manager (e.g., sudo pacman -S gamescope or sudo apt install gamescope). The Gamescope card on the Launch page shows a warning if it's not found.
    • Black screen with Gamescope - Verify that the configured resolution is supported by your monitor. Try disabling HDR in Gamescope.
    • HDR not working - HDR in Gamescope requires driver support. Ensure your GPU driver supports HDR and is up to date.

    GameMode issues

    • GameMode not installed - Install the gamemode package (e.g., sudo pacman -S gamemode or sudo apt install gamemode). The option is disabled with a warning on the Launch page if missing.
    • GameMode has no effect - Make sure gamemoded (the daemon) is running. Test with gamemoded -t.

    Keybindings on wrong device

    Linux joystick instance numbers can differ from what Star Citizen expects. Use the Keybindings page to reorder your joystick instances via drag and drop.

    Wayland issues

    • Wayland support is experimental. If you experience problems, disable it on the Launch page to fall back to XWayland.
    • Fractional scaling (125%, 150%) is not compatible with native Wayland mode.

    The launcher starts but no window appears (Wine 11.14 and 11.15). In those two Wine versions the Wayland driver creates the RSI Launcher's surfaces, loses their toplevel role again and never receives a size from the compositor — the launcher demonstrably runs (its processes are there) but stays invisible. Two ways out, in this order:

    • Use a runner with Wine 11.16 or newer. It is fixed there, and it is the route without side effects.
    • Otherwise enable Render via XWayland on the Launch page. The window then appears, but the mouse can react offset in the game (see the next point). The app warns at launch when Wayland is combined with one of the affected versions.

    The mouse reacts offset in the game, or elements only flicker. This is a property of XWayland rather than a bug in the app: the pointer cannot be warped there while it is visible, so the game works with the wrong coordinates. It shows up most clearly on multi-monitor setups where the game's monitor is not at the left edge of the desktop layout. Native Wayland has a dedicated protocol for this by now (wp_pointer_warp_v1); it takes effect when both sides support it — Wine 11.9 or newer and KWin 6.4 or newer (or Mutter 49+, wlroots 0.19+). In practice: XWayland box off, Wayland on, runner 11.16 or newer. If you have to stay on XWayland, the LUG wiki page on mouse and keyboard lists further remedies (turn off the launcher overlay, set r_width/r_height in USER.cfg, gamescope with --force-grab-cursor).

    GitHub API rate limit

    If you see rate limit errors when browsing Wine runners or checking for updates, set a GitHub personal access token in Settings. This increases the limit from 60 to 5,000 requests per hour.

    Known Limitations

    • Penguin Citizen is in early development. Some features may be incomplete or change between versions.
    • The application currently supports English and German. Other UI languages are not yet available.
    • Star Citizen's anti-cheat (EasyAntiCheat) must be compatible with Wine/Proton for the game to run.
    • Some Wine runners may work better than others depending on your hardware and distribution.

    Getting Help

    If you encounter an issue not covered here:

    • Check the GitHub Issues page for known bugs and feature requests
    • Open a new issue with your log files and system information
    • Visit the Star Citizen LUG Wiki for general Linux-related Star Citizen help
